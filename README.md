# Video Download Grabber (local-only MV3 extension)

Detect playable video on any tab and download it locally — no backend, no third-party calls. **YouTube is not supported** (its delivery is encrypted/obfuscated; the extension doesn't run there at all).

## What it does

- **Works anywhere except YouTube**: `<all_urls>` host + content-script coverage (all frames), so feeds, embeds, and players on any other site are detected. YouTube / youtu.be / youtube-nocookie pages and `googlevideo.com` traffic are excluded in the manifest and the worker. (Chrome will show a broad-access warning at install — that access is what lets it see video traffic; everything stays local.)
- **Many video types**: direct `mp4/m4v/webm/ogv/mov/mkv/avi/flv/wmv/mpg/3gp` (by URL and by `content-type`), HLS (`.m3u8`, incl. fMP4 with `#EXT-X-MAP` init segments), DASH (`.mpd`, incl. init segments). A conservative chunk-score keeps raw stream fragments (`.m4s`, init segments, `/avc1/0/0/…` paths) out of the list — the playlist item covers them — while real dated/numbered file URLs are never demoted.
- **Page-blob files**: players that fetch a whole file and play it via `URL.createObjectURL(new Blob(...))` expose no manifest and no chunk traffic. The page hook retains such Blobs (bounded registry) and the extension streams the exact bytes out in ≤4MB slices — no re-fetch, so one-time/expiring URLs keep working.
- **Refuses DRM cleanly** (HLS `#EXT-X-KEY` METHOD != NONE, DASH `<ContentProtection>`, `pssh` boxes in grouped chunks, any EME/Widevine-style path in captured players) — never fetches/decrypts protected segments. AES-128 key fetching is deliberately not implemented. Blob/MSE player buffers without another source are shown with an explanation, not a dead button.
- **MSE/blob capture**: when a player feeds segments via MediaSource (only a `blob:` URL is visible), a page hook copies the exact appended bytes per audio/video track, in order. Downloading a capture reassembles the lossless buffered track (`.mp4` for fMP4) — no re-download, no re-encode, works even for one-time signed URLs. 64 MB/track in-page capture cap (partials labeled), oldest-session eviction, cancellable. Captures that outgrow the 1.5 GB assemble cap save as sequential `.partN` files (each carries the init header and plays standalone) instead of failing. EME-tainted sessions, or any session on a page using DRM, are refused rows — never downloadable. Grouped chunks are validated before they become a file (container check, init-header check, error-page rejection) — unplayable groups refuse with a clear message instead of a corrupt download.
- **Resilient detection**: network layer (`webRequest`) + continuous page scan (MutationObserver, shadow DOM, same-origin iframes, report-on-play).
- **MSE/blob correlation**: `.ts`/`.m4s`/chunk traffic is tracked per tab and grouped by URL pattern — 4+ sequential chunks promote to a downloadable grouped item, linked to the player that triggered them. A parsed manifest automatically supersedes raw groups from the same directory.
- **Manifests that refuse to be re-fetched**: playlists are read through a fallback chain instead of a single request — (1) the bytes we already cached, (2) **the playlist bytes the player itself downloaded** (the MAIN-world hook keeps the m3u8/mpd bodies it sees, bounded by count/chars/TTL and rate-limited, so nothing is re-requested at all), (3) a worker fetch with replayed headers/referrer, (4) a fetch issued from the **page's own JS world** — page cookies, `Referer`, `Origin`, `Sec-Fetch-*` and network fingerprint, i.e. exactly the request the playing video already made. Token-expired links, hotlink-protected CDNs and `404`/`403`-instead-of-manifest answers that used to show *Manifest fetch failed* now resolve. When even that fails the row says which layer said what (`extension: 404 · page: 404`) and offers a **Retry** button next to the message.
- **Stream chunks a CDN refuses the extension**: plenty of sites serve the playlist to the page but answer the extension's request for the *segment files* with 403/404, or with an HTML "hotlink denied" page disguised as video (a different `Origin`/`Referer`/`Sec-Fetch-*`, no page cookies, no bot clearance). When a chunk is refused that way — and only that way — the segment is re-requested **from the page's own JS world** and streamed back in ≤4MB slices, then validated and assembled exactly like a direct one. The variant playlist read uses the same fallback, so a gated HLS/DASH job no longer dies before the first byte. Bounded on purpose: 2 page fetches at a time, 40 chunks per job (then it fails with a clear reason instead of thrashing), at most two chunks held in the page, and a page that can't fetch the chunk falls back to the original error. 5xx/throttle/timeout failures are **never** relayed — those aren't about who is asking, so a flaky CDN is not made slower. Downloads that needed it say so on completion ("Fetched through this page's own session").
- **Frame-aware page context**: the frame a video was seen in (`webRequest` frameId for network hits, the reporting frame for element/hook hits) is stored with the item and carried onto the job, so every page-context step — reading the playlist the player already fetched, a page-world fetch, a relayed chunk, a Blob/MSE pull — is addressed to **that** frame: the one whose `Referer`, cookies and player buffer the site's own requests used. The right-click menu also targets the frame you clicked in. A frame that doesn't hold a page Blob or capture **declines** (no side effects) instead of failing bytes it never had, and the worker walks the tab's frames until one accepts. Frame ids are recreated by navigation, so every targeted send falls back to a tab-wide send — a stale id can never strand a download.
- **Header replay**: the exact `Authorization` / custom `X-*` headers and referrer the page used are recorded per request and replayed on re-fetch (auth only to the same origin it came from; cookies are never stored and can't be replayed via fetch — the page-context fallbacks above cover those). This fixes most "found but 403 on download" cases.
- **API-wrapped manifests**: a MAIN-world hook transparently watches the page's own fetch/XHR for JSON responses embedding `.m3u8`/`.mpd` URLs (size-capped, media traffic skipped, bodies never leave the page — only extracted URLs). No YouTube-specific handling.
- **Background downloads**: an offscreen document fetches segments (**8 parallel**, per-segment **timeouts + retries**, 2000-segment safety cap) and assembles the file, then saves it **directly via a document download** — bytes never cross extension messaging (legacy data-URL handoff remains as a small-file fallback). Videos past the 1.5 GB in-memory safety cap no longer fail: they save automatically as sequential `name.part1.ext`, `name.part2.ext`, … files (each validated; fMP4 parts carry the init header so every part plays standalone — join them in order for the full video). Direct file URLs (including gated script endpoints like `.php`) are fetched **with the page's own auth context** (cookies + captured same-origin headers + referrer) with error-page validation and byte progress — oversized files hand over to the browser automatically. Split A/V streams (video-only + audio-only variants, MSE capture tracks) are **merged into one playable `.mp4` with sound** by a built-in fMP4 muxer — no ffmpeg, no re-encode, no backend; merges past the cap save as per-track part sets with an ffmpeg one-liner in the completion note. Non-fMP4 pairs fall back to two files with a clear note. Popup can close — progress (`Fetching… n/m` → `Assembling…` → `Saving…`) persists and live-updates on reopen. Jobs are **cancellable**. Output extension is sniffed from bytes (`.ts` vs `.mp4`), not guessed.
- **Resumable downloads**: fetched segments are written to the extension's origin-private file system (OPFS) as they arrive, so a crash, browser restart, or extension reload no longer loses progress. Interrupted HLS/DASH/grouped jobs come back **paused** with everything already downloaded kept — hit Resume and only the missing segments are fetched (fresh signed URLs are re-resolved, and persisted segments are matched against the playlist's segment count so a stale cache is never reused). Direct-file and page-capture jobs can't be resumed (their bytes only ever existed in the page) and say so instead of pretending. Cancelling a job drops its cached segments, and caches for jobs that no longer exist are pruned at startup.
- **Hands-free entry points**: right-click any `<video>` → **Download this video** (context menu), or press **Alt+Shift+D** to download the best video on the page without opening the popup (playing video first, then the largest player). **Alt+Shift+V** opens the popup. Both routes resolve the video through the same classifier the popup uses, so the download path, quality selection, muxing and DRM refusal all behave identically.
- **Site-adapter registry**: coverage for sites whose media never becomes a sniffable request lives in the pluggable `src/lib/adapters/` folder — each adapter declares `{ match: (url) => boolean, extract: (page) => MediaItem[] }` using only pure snapshot data (page URL, title, already-found media URLs). The content script forwards adapter output through `VIDEO_ELEMENTS.adapterItems` / `COLLECT_FOR_POPUP`, and the background worker merges it with the same classify → dedupe → manifest-parse → persist → badge normalization as generic detections. Adapters are hard-blocked on YouTube at the registry level (plus the manifest, content-script, and worker exclusions), run over the same snapshot the generic scan produces, and a throwing adapter is skipped instead of breaking the scan. Adding a site is one adapter module plus one registry entry; the generic engine stays untouched.
- **Separate-audio HLS masters**: master playlists that keep audio in its own rendition (`#EXT-X-MEDIA:TYPE=AUDIO` + `AUDIO="group"` on the variant — common on premium/CDN setups) are now paired instead of silently downloading a silent video. The audio playlist is attached to the video variant and muxed into one `.mp4` by the same fMP4 muxer used for split A/V; TS pairs fall back to two files, and variants that already carry a `mp4a`/`opus` codec are left alone.
- **Connection-aware quality hint**: when a manifest offers several qualities, the extension samples the first couple of segments (a few hundred KB, cached per video for 10 minutes, throttled to at most two at a time and three per popup) and badges the highest quality the measured throughput can sustain with **— Recommended**, leaving the user's preselection alone. Nothing is measured when the item has a single quality, and a failed probe simply means no badge.
- **Batch mode**: the popup's **Select** toggle puts a checkbox on every downloadable card (and makes the whole card a tap target). **Download selected** queues them with a **2-at-a-time concurrency cap** (1–4 in settings, shared with any other running download so a page with ten videos never opens ten parallel fetchers), while a live queue line reports *downloading / waiting / done / failed*. Selecting picks each card's chosen quality.
- **Rolling speed + ETA**: the worker keeps a short sliding-window rate per job (`rateBps`) and the popup renders `12.0 MB/s • ~2 min left` on every progress line — for byte streams ETA is exact, for playlists it extrapolates from the average segment size. A stalled transfer's speed drops instead of being masked by a cumulative average.
- **Filename templates + download subfolder** (options page): name saved files with patterns like `{title} [{quality}].{ext}` (`{title} {quality} {ext} {host} {type} {date}` available) and drop them into a relative subfolder such as `Videos/down-stream`. Applied at download time in the worker, so every entry point (popup, batch, right-click, shortcut, history re-download) honours them. Empty groups collapse cleanly (`{title} [{quality}]` → `My clip.mp4` for a source with no quality), and an empty pattern keeps the detected name.
- **Completion notifications**: finished downloads raise a system notification with a **Show in folder** action (reveals the file via `chrome.downloads.show`). Toggle it off in settings.
- **Download history** (options page → History): every settled download (done / failed / cancelled) is recorded with its title, saved path, quality, size and source link. **Re-download** re-resolves fresh signed URLs — through the still-open page when it's around (full auth context), otherwise by re-parsing the manifest and reissuing the job; **Show in folder** and **Copy link** sit next to it. Capped at 300 rows and clearable.
- **Popup extras**: parsed manifests dominate the list (raw chunk groups and blob placeholders auto-hide when qualities exist), quality dropdowns sorted best-first with best preselected (single quality = one button, audio-only tracks labeled), split A/V masters download as `*-video.ts` + `*-audio.m4a` with a clear note, per-card **Copy link** (works even with the worker down; direct files can also download worker-free), real thumbnails (video poster → nearby page image → API-bundled poster), per-video **titles** (post text/aria-label near the player, page title as fallback) shown on cards and used for file names, resolution/duration/playing metadata, newest-first list, and a worker-independent page scan so an empty worker never means an empty popup.

## Load unpacked in Chrome/Brave

1. `npm install`
2. `npm run build`
3. Open `chrome://extensions` (or `brave://extensions`) → enable **Developer mode** → **Load unpacked** → select `dist/` (after build). Confirm version **1.0.0**.
4. **Reload the web page's tab** after installing/updating (content scripts only inject into fresh loads).
5. Test: MDN `flower.mp4` (direct), `https://test-streams.mux.dev/x36xhzz/x36xhzz.m3u8` (HLS master), `https://dash.akamaized.net/akamai/bbb_30fps/bbb_30fps.mpd` (DASH), any X/Twitter feed video.
6. Click the extension icon → pick quality → Download. You can close the popup.
7. Or skip the popup entirely: right-click a video → **Download this video**, or press **Alt+Shift+D**.

If the popup ever reports the worker unreachable: use **Reload extension now**, reopen — and if it persists, `chrome://extensions` → Developer mode → this extension → **Service worker** shows its log.

## Permissions

`activeTab, webRequest, webNavigation, downloads, storage, scripting, offscreen, clipboardWrite, contextMenus, notifications` + `<all_urls>` hosts (YouTube hosts excluded). No remote servers. Open the options page from the popup's ⚙ button (or `chrome://extensions` → Details → Extension options) for filename/subfolder, notification and batch settings plus the download history.

Keyboard shortcuts (`Alt+Shift+D` download best video, `Alt+Shift+V` open popup) are remappable at `chrome://extensions/shortcuts`.

## Scripts

- `npm run dev` — Vite dev (limited for MV3; prefer `build` + reload).
- `npm run build` — `tsc --noEmit && vite build` → `dist/`.
- `npm test` — Vitest unit suite (`npm run test:watch` to iterate).
